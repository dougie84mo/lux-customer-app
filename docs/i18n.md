# Translations (i18n) — LUX Booking

English + Spanish since 2026-09-28. **Every string a person reads goes
through `t()`; every date, time, amount and duration goes through
`lib/format.ts`.** A new hardcoded string is a bug.

## Pieces

| File | Job |
|---|---|
| `lib/i18n.ts` | i18next init (bundled resources, synchronous), `deviceLocale()`, `currentLocale()`, `tMessage()` |
| `lib/format.ts` | `useFormat()` → `date(d, style)`, `fromNow`, `money(cents)` (charges, receipts), `price(dollars)` (catalogue prices, "$25"), `duration(min)`; plus the bare `formatDate` / `formatMoney` / … for non-React code |
| `lib/localeSync.tsx` | the saved choice (Phone setting / English / Español, AsyncStorage), `LocaleSync` mirrors the language on screen into `users.locale` (0195) for push / email / SMS / Stripe |
| `locales/{en,es}/<ns>.json` | the dictionaries — one JSON per namespace |
| `i18next.d.ts` | typed keys: `t()` only accepts keys that exist in `locales/en` |
| `scripts/i18n-check.mjs` | `node scripts/i18n-check.mjs` — es has exactly en's keys and `{{variables}}` |

Namespaces (one per screen family): `common` (actions, statuses, errors,
language, tabs), `auth`, `account`, `discover`, `booking`, `payments`,
`inbox`, `photos`.

## Rules

1. **Screens:** `const { t } = useTranslation(['booking', 'common']);` — own
   namespace first, `common` second, then `t('slots.title')` and
   `t('common:actions.save')`. Reuse `common` before adding a duplicate.
2. **Keys** are nested by screen/section, camelCase, and describe the
   meaning, not the English: `booking.confirm.depositNotice`, not
   `booking.youWillPay`.
3. **Variables, never concatenation.** `t('x.cancelledAt', { shop, when })`
   with `"{{shop}} cancelled your booking for {{when}}"`. Spanish word
   order differs; a sentence split across two keys cannot be translated.
4. **Plurals:** i18next suffixes — `"visits_one": "{{count}} visit"`,
   `"visits_other": "{{count}} visits"`, called as `t('visits', { count })`.
   Spanish needs the same two forms.
5. **Dates / money:** `const f = useFormat();` then `f.date(iso, 'weekdayDateTime')`,
   `f.money(cents)`, `f.duration(45)`. No `$${(c/100).toFixed(2)}`, no display
   pattern passed to date-fns `format`. `format(d, 'yyyy-MM-dd')` for query
   keys / RPC arguments is data and stays.
6. **Non-React code** (lib/ hooks, thrown errors): `i18n.t('ns:key')` from
   `@/lib/i18n`, or throw `new Error('payments:errors.cardDeclined')` and
   show it with `tMessage(err.message)`. Zod messages in `lib/schemas.ts` are
   keys (`'auth:validation.email'`) rendered with `tMessage(...)`.
7. **Server text stays as sent.** Tenant data (business, service, staff
   names, descriptions) and raw Postgres/Edge error messages are not
   translated. Wrap only our own fallback copy.
8. **Spanish style:** informal *tú*, US Spanish; "cita" (appointment),
   "reservar" (book), "salón" / "negocio", "estilista", "depósito",
   "recibo", "reseña". Keep brand names (LUX Booking, LUX Mirror) and
   STOP/HELP keywords untranslated.
9. **Tests:** Jest loads the real English dictionaries (`jest.setup.ts`), so
   `getByText('Pay now')` keeps working — keep the English wording of
   tested strings unless you update the test.

## Adding a language

1. Extend the `0195` check constraints on `users.locale` and
   `businesses.default_locale` (a migration in `../app`).
2. Extend `AppLocale` in `lib/i18n.ts` and the `PATTERNS` table in
   `lib/format.ts`.
3. Add `locales/<lang>/` with every namespace, and wire it in `locales/index.ts`.
4. Add a picker option in `app/(app)/settings.tsx`.
5. Register the react-native-paper-dates pack in `app/_layout.tsx`.
6. Run `node scripts/i18n-check.mjs`.
